## B. Backend blockers (block frontend live-integration)

The frontend WS notification push is built against mock frames and gated by `API_MODE === 'mock'` until these land.

### B1. `/ws` browser auth — query-token or subprotocol
- **Problem:** Browser `WebSocket` cannot set the `Authorization` header the backend middleware requires.
- **Fix:** Accept a `?token=` query param (or `Sec-WebSocket-Protocol` subprotocol) in the WS middleware, validate it the same way as the JWT bearer.
- **Unblocks:** WS notification push (M-F5 T2) live mode.
- **REFACTOR-TODO line:** 48 (ws hub rewrite).

### B2. WS hub rewrite with Redis pub/sub fan-out
- **What:** Rewrite the in-memory `ws` hub to use Redis pub/sub for fan-out (needed when the API runs >1 instance). This is for notification push — the chatbot (Qwen3.5) is excluded from this phase.
- **REFACTOR-TODO line:** 48.

### B3. Central error-mapper with stable `code`s
- **What:** TDD §4.3 — a central error-mapper middleware that converts service-layer `models.Err*` errors into the `{error:{code, message, details}}` envelope with stable, documented `code` strings.
- **Current state:** M-F1 ships a frontend-side `classifyApiError` message→code mapper as an interim adapter. When the backend lands stable codes, the frontend adapter can be simplified.
- **REFACTOR-TODO:** Referenced in frontend TODO "Backend dependencies" line 94.

### B4. CORS `CLIENT_ORIGIN` in dev compose
- **What:** Add the frontend origin(s) to the backend's CORS allowed-origins in the dev docker-compose file so the Vite dev server can talk to the Fiber API in live mode.
- **REFACTOR-TODO:** Frontend TODO "Backend dependencies" line 95.
