M-F4 is a large milestone. I'll implement it in 7 committed tasks, each passing all gates (lint, format, typecheck, tests, build). Each task builds on the previous one.

## Task 1 — Foundation: types, auth RBAC, deps, admin shell

**Goal:** Expand the `User` type for 5 staff roles + permissions, install TanStack Table, add admin API methods, create the admin shell with staff guard and permission-keyed nav, and add admin mock handlers (at least the auth/identity + dashboard stubs).

### Changes:
1. **`src/lib/types.ts`**: Expand `User.role` to `'customer' | 'super_admin' | 'content_editor' | 'travel_planner' | 'ecommerce_operator' | 'customer_service'`. Add `roles?: string[]` (backend JWT carries `roles: []`; keep `role` as the primary for backward compat — `role` = first staff role or `'customer'`). Add `StaffRole` type union. Add `Permission` type union matching the 16 backend permission keys. Add admin DTOs: `AdminProduct`, `AdminOrder`, `AdminItinerary`, `ShippingTier`, `OptionRate`, `AuditLog`, `AdminUser`, `DashboardTraffic`, `DashboardSales`, `DashboardFunnel`, `MediaAsset`, `BulkImportSummary`, `QuoteLineItemInput`.

2. **`src/lib/auth.tsx`**: Add `hasRole(role)`, `hasPermission(perm)`, `isStaff()` helpers to `AuthValue` — derived from `user.roles` (or fallback to `user.role`). These gate admin nav + route access.

3. **Install deps**: `pnpm add @tanstack/react-table`

4. **`src/lib/api.ts`**: Add admin API methods for every `/admin/*` endpoint (grouped by module: content, products/skus, orders, itineraries, media, certificates, settings, dashboard, users, audit).

5. **`src/routes/$locale/admin/` route directory**: Create:
   - `src/routes/$locale/admin.tsx` — the admin layout route with `beforeLoad` staff guard (redirects non-staff to `/$locale` with a toast). Renders `AdminShell` (sidebar nav + `<Outlet>`).
   - `src/routes/$locale/admin/index.tsx` — dashboard landing (redirect to first permitted module or show dashboard).

6. **`src/components/admin/AdminShell.tsx`**: The admin chrome — fixed sidebar with permission-keyed nav (Dashboard, Content, Products, Orders, Itineraries, Settings, Users, Certificates, Audit Log). Top bar with user email + logout. No Header/Footer (like magazine pages — conditionally excluded in `LocaleShell`).

7. **`src/routes/$locale.tsx`**: Add `/admin` to the `isMagazine`-like check so admin pages skip the storefront Header/Footer/ConsentBanner. Admin has its own chrome.

8. **Mock handlers in `src/mocks/transport.ts`**: Add admin route handlers — starting with `GET /admin/orders` (list), `GET /admin/products`, `GET /admin/ceramicstory`, `GET /admin/engage`, `GET /admin/artists`, `GET /admin/analytics/*` (dashboard stubs), `GET /admin/audit-log`. More handlers added in later tasks as needed.

9. **i18n**: Add `admin.*` keys to both `en-US.ts` and `zh-CN.ts` — nav labels, common table headers, status labels, action buttons.

10. **Demo user**: Update the mock admin user to carry `roles: ['super_admin']` so the `hasPermission` helper works. Also seed a `content_editor` demo user for testing role-keyed nav.

**Commit:** `feat(frontend): M-F4 T1 — admin foundation (types, RBAC, shell, deps)`

## Key architectural decisions:
- **Admin chrome**: Admin routes skip the storefront Header/Footer/ConsentBanner (like magazine pages). `AdminShell` provides a sidebar + topbar.
- **Client-rendered**: All admin pages use `useEffect` + `useState` (auth-gated, personalized — no SSR benefit).
- **TanStack Table**: Installed for all admin lists (sortable, filterable columns).
- **Forms**: Hand-rolled with zod validation (matching existing patterns — no react-form library needed).
- **Mock mode**: Every `/admin/*` endpoint gets a mock handler so the full CMS works without the backend.
- **RBAC**: `hasPermission()` helper gates nav visibility + action buttons. `beforeLoad` staff guard on the admin layout route redirects non-staff.
